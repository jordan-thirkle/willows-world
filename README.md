# Willow's World

**Her voice. Her stories. A world that grows with her.**

Willow's World begins with a real parent-and-child ritual: learning to read together. A parent records the child's real reading voice, and an AI-assisted production pipeline turns that ordinary recording into a polished, consistent illustrated experience that can be watched, played and shared.

The founding loop is:

**Record → Transform → Watch / Play → Share**

One approved reading performance should drive:

- an interactive mobile-first Story Woods read-along;
- a 16:9 YouTube episode;
- a 9:16 Shorts / TikTok / Reels episode;
- learning progress that changes Willow's World.

## Product principles

- **The real child voice is the hero.** AI assists production; it does not replace the reading with a voice clone.
- **One performance, many outputs.** App and video outputs share the same approved timing, scenes and canonical artwork.
- **Consistent world art.** Willow's canonical continuity is brown hair, blue eyes and purple glasses.
- **Parent controlled.** Preview/approval precedes export or publication.
- **Mobile first and cross-platform.** Expo is the application foundation; Remotion is the deterministic video renderer.
- **A world, not a dashboard.** Story Woods is the first destination. Word Garden, Maker Meadow, Discovery Hill and games can grow around it after the founding loop is excellent.
- **No AI slop.** Warm, authored, tactile children's illustration and thoughtful motion over generic AI-product aesthetics.

## Episode 001

The existing real reading recording is the development performance for Episode 001. It is used to prove the complete production machine before asking Willow for a new recording.

The first milestone is not 'more features'. It is being able to watch/play something and feel that a normal bedtime recording has become a professional Willow's World experience.

## Engineering workflow

GitHub is the source of truth. Meaningful work uses branches and pull requests. Vercel previews make milestones visible and comparable. Temporary ZIP files are exports, never canonical project state.

When blocked: **detect → reproduce → investigate root cause → identify alternatives → implement the durable fix → verify → document → continue the original goal.**
