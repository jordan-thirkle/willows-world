# Willow's World — Operating Model

## Mission

Ship Willow's World as a safe, durable, professional By JTT product whose defining experience is **Record → Transform → Watch / Play → Share**.

## Hierarchy

When priorities conflict, use this order:

1. Child safety, privacy, rights and preservation.
2. Truth of the real performance and parent-approved corrections.
3. Quality/completion of the current product gate.
4. Reliability, verification, recovery and maintainability.
5. Native/web distribution readiness.
6. Discoverability and responsible growth.
7. Expansion features.

## Stage gates

- **P0 Product-complete alpha** — Episode 001 proves the founding loop end-to-end.
- **P1 Distribution-complete beta** — real Expo iOS/Android clients, durable private persistence and family-data controls.
- **P2 Public-launch complete** — public/private trust separation, rights-safe content, store/web readiness and release operations.
- **P3 Organic-growth launch** — discoverable public web, SEO, approved media distribution and By JTT marketing system.

Do not call a stage complete because code exists. A stage completes when its evidence gate passes.

## Work selection

Choose the highest-value unresolved item in the earliest incomplete gate. A later-gate task is allowed only when it is non-blocking preparation and does not displace earlier-gate work.

Reject scope that does not improve the current gate, remove a material risk, or establish required verification.

## Change lifecycle

`understand → design/plan → branch → implement vertical slice → test → independent review → preview/device verification → document evidence → PR → merge → continue`

Prefer small independently testable slices over broad rewrites. Preserve working experiences while moving state/logic behind durable interfaces.

## Blocker lifecycle

`detect → reproduce → root cause → identify alternatives → implement durable fix → verify → document → resume original goal`

A tooling/vendor limitation is a problem to route around where feasible, not permission to abandon the product goal. Never falsify verification when the environment cannot run a required check; record the limitation and find the strongest independent alternative.

## Evidence policy

Completion claims require fresh evidence appropriate to the change: tests, typecheck/lint/build, rendered UI/browser inspection, native simulator/device flow, security/privacy review, output comparison, or production health evidence.

Repository documentation is intent, not proof that runtime behavior works.

## Data and repository policy

GitHub contains code, safe fixtures, schemas, plans and evidence. It does not contain private child recordings, credentials, production secrets or accidentally public family data.

Source performances and parent-approved corrections are canonical. AI/provider outputs are derived, versioned and replaceable.

## Growth policy

SEO, public episodes, YouTube/short-form output and X marketing amplify a product that works. They must not distort the child-facing experience or encourage compulsive engagement. Public content crosses the private/public boundary only through explicit approval and rights checks.

## Project-boundary policy

The childhood archive project may inform By JTT standards such as provenance, preservation and professional operations. Willow's World remains its own product with its own north star, domain model, roadmap and release gates.
