# Willow's World — Roadmap Change Policy

The P0→P3 model is durable but not dogma. Change it when new evidence materially changes the product, safety/rights constraints, platform requirements or critical technical path.

A roadmap change should record:

- new evidence;
- which existing assumption/gate is affected;
- why the change improves user outcome, safety or delivery feasibility;
- what is removed/deprioritized as a result;
- whether acceptance/verification documents must change.

Do not change the roadmap merely because a new tool, AI capability or feature idea is interesting.
